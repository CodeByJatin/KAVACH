# KAVACH Platform — Glossary & Terminology Reference
# This document helps the AI assistant explain KAVACH concepts clearly to users.

======================================================================
KAVACH PLATFORM CONCEPTS
======================================================================

KAVACH
  A centralized cryptographic monitoring and attack surface management
  platform. It discovers subdomains, scans TLS configurations, evaluates
  Post-Quantum Cryptography (PQC) readiness, and generates security
  ratings for enterprise infrastructure.

PQC Score (0-1000)
  A proprietary security index calculated per asset. Evaluates four
  dimensions: TLS protocol version, cipher suite strength, key exchange
  mechanism, and PQC algorithm adoption. Higher = more secure.
  Bands: Elite (800+), Strong (600-799), Standard (400-599),
  Legacy (100-399), Critical (0-99).

CBOM (Cryptographic Bill of Materials)
  A structured inventory listing every cryptographic protocol, algorithm,
  key, and certificate across an organization's infrastructure. Think of
  it like a "software bill of materials" but for encryption. Helps track
  what needs upgrading for quantum readiness.

CT Logs (Certificate Transparency Logs)
  Public, append-only logs that record every TLS certificate issued by
  Certificate Authorities. KAVACH mines these to automatically discover
  all subdomains associated with a target domain — no brute-forcing needed.

Discovery
  The automated process where KAVACH queries CT logs, DNS records, and
  other passive sources to find all subdomains and assets belonging to
  a domain. This happens before any deep scanning.

Deep Scan
  After discovery, KAVACH connects to each asset via TLS handshake using
  sslyze to extract: TLS version, cipher suites, certificate details
  (key type, key length, CA, expiry), and server software. This data
  feeds into the PQC scoring engine.

Attestation Certificate
  A formal PDF document certifying the overall cryptographic posture of
  a domain or enterprise. Includes the average PQC score, rating band,
  and an assessment of quantum readiness. Used for compliance reporting.

======================================================================
SECURITY CONCEPTS
======================================================================

SNDL (Store Now, Decrypt Later)
  An attack strategy where adversaries intercept and store encrypted
  network traffic today, planning to decrypt it in the future when
  quantum computers become powerful enough. This makes upgrading
  encryption urgent even before quantum computers arrive.

Cryptographic Agility
  The ability of a system to quickly swap cryptographic algorithms
  (e.g., replacing RSA with ML-KEM) without requiring a full system
  rebuild. Organizations with high cryptographic agility can respond
  to new threats faster.

Forward Secrecy (PFS — Perfect Forward Secrecy)
  A property where each session uses a unique key. Even if the server's
  private key is later compromised, past sessions remain secure.
  Enabled by: ECDHE and DHE key exchanges. Required in TLS 1.3.

Hybrid Cryptography
  Using both a classical algorithm (e.g., X25519) and a PQC algorithm
  (e.g., ML-KEM-768) together in a single TLS handshake. Provides
  security against both classical and quantum attackers during the
  transition period. Example: X25519Kyber768Draft00.

Risk Levels in KAVACH
  • Critical — Severe vulnerabilities, outdated crypto, immediate action needed
  • High — Significant weaknesses, should be prioritized
  • Medium — Acceptable but upgrades recommended
  • Low — Meets modern standards, minor improvements possible

======================================================================
COMMON USER QUESTIONS (FAQ)
======================================================================

Q: What does a PQC score of 750 mean?
A: Strong cryptographic posture. The asset uses modern TLS and cipher
   suites but hasn't yet adopted post-quantum algorithms like ML-KEM.
   Recommend hybrid TLS migration.

Q: Why is my RSA-2048 asset scored as "Medium" risk?
A: RSA-2048 is classically secure for now, but quantum computers running
   Shor's algorithm could break it. NIST recommends migrating to ML-KEM
   or ML-DSA. It's not an emergency but should be planned.

Q: Is TLS 1.2 still safe?
A: For now, yes — if properly configured with strong cipher suites
   (AES-256-GCM + ECDHE). But TLS 1.3 is strongly preferred because
   it removes all legacy insecure options and requires forward secrecy.

Q: What should I do if my score is below 400?
A: Priorities: (1) Upgrade to TLS 1.3, (2) Disable weak ciphers like
   RC4/3DES/CBC, (3) Use ECDHE for key exchange, (4) Plan ML-KEM
   hybrid deployment for PQC readiness.
